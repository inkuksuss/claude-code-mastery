# Claude 명령어: Update Roadmap

`docs/ROADMAP.md`를 열어 실제로 완료된 작업을 찾아 완료 표시(✅)와 변경 사항 요약을 반영합니다.

## 사용법

```
/update-roadmap
```

인자 없이 실행하면 로드맵 전체를 훑어 완료 후보를 찾습니다. 특정 Task 번호를 인자로 주면(`/update-roadmap 006`) 해당 Task만 검증하고 반영합니다.

## 프로세스

1. `docs/ROADMAP.md`를 읽어 아직 `✅`가 없는 Task 중 완료 후보를 찾는다.
2. 각 후보 Task에 대해 "관련 파일" 섹션에 나열된 파일이 실제로 존재하고 요구된 내용을 담고 있는지 확인한다(`Read`/`Grep`으로 직접 검증 — Task 설명만 보고 완료로 단정하지 않는다).
3. `/tasks/XXX-*.md` 작업 파일이 있으면 그 안의 구현 단계·수락 기준 체크박스가 모두 체크되어 있는지 함께 확인한다.
4. `npm run lint`, `npm run build`가 통과하는지 확인한다. 실패하면 해당 Task를 완료로 표시하지 않고 실패 내용을 보고한다.
5. 검증을 통과한 Task만 `docs/ROADMAP.md`에서:
    - Task 헤더 앞에 `✅` 추가 (예: `- **Task 006: ...**` → `- ✅ **Task 006: ...**`)
    - 헤더 하위에 `- 변경 사항: ...` 줄을 추가해 실제로 무엇이 구현되었는지 1~3문장으로 요약(기존 Task 001~005 항목의 문체를 따른다)
    - 해당 Phase의 모든 Task가 완료되면 Phase 제목에도 `✅`를 추가
6. `## 마일스톤 매핑`, `## 리스크 대응 매핑` 표에 이번에 완료된 Task와 관련된 리스크가 있으면 해소 여부를 함께 갱신한다(예: 스파이크 Task 완료로 리스크가 해소된 경우).
7. 무엇을 완료로 표시했고, 무엇을 검증했지만 아직 완료로 볼 수 없는지(부분 구현, 테스트 미통과 등) 한국어로 요약해 보고한다.

## 완료 판정 기준

- **완료로 표시하지 않는 경우**: 코드가 일부만 작성됨, lint/build 실패, 수락 기준 중 하나라도 미충족, "Task 011에서 연결 예정" 같은 의도적 스코프 아웃이 아직 해소되지 않음.
- **완료로 표시하는 경우**: 관련 파일이 실제로 존재하고 요구 내용을 구현했으며, lint/build 통과, 수락 기준 충족(비즈니스 로직 Task는 Playwright MCP 등으로 실제 동작까지 확인된 경우).
- 애매하면 임의로 판단하지 않고 사용자에게 확인한다.

## 참고사항

- 이 커맨드는 로드맵 문서만 갱신한다. 구현 자체나 `/tasks` 작업 파일 내용을 대신 작성하지 않는다.
- 완료 표시를 되돌리거나(✅ 제거) 이미 완료된 Task 내용을 재작성하지 않는다 — 새로 완료된 항목만 추가로 반영한다.
- 여러 Task가 동시에 완료 후보라면 각각 독립적으로 검증하고, 일부만 기준을 충족해도 해당 항목만 반영한다.
