# 노션 견적서 웹 뷰어 개발 로드맵

노션에 입력하면 끝. 클라이언트는 링크로 보고 PDF로 받는다.

## 개요

노션 견적서 웹 뷰어는 **소규모 사업자·프리랜서(공급자)와 견적서를 받는 클라이언트**를 위한 제품으로, 공급자가 이미 쓰는 노션을 어드민으로 삼고 클라이언트에게는 항상 최신 상태의 웹 링크와 PDF를 제공합니다. 다음 기능을 제공합니다:

- **토큰 링크 웹 뷰**: `/quote/[token]` — 회원가입 없이 링크 하나로 항상 최신 견적서 열람
- **서버 PDF 다운로드**: 한글 폰트를 임베딩한 A4 세로 견적서 PDF를 서버에서 생성
- **노션 = 어드민**: 별도 관리 화면 없이 노션 Database가 곧 견적서 관리 도구 (읽기 전용, 싱글 테넌트)
- **간이 로그인**: 인증 서버 없이 브라우저 `localStorage`에 사용자명을 저장해 헤더에 표시하는 데모 수준 로그인

> 이 제품은 **읽기 전용 뷰어**입니다. 전자서명, 결제, 이메일 발송, 커스텀 PDF 템플릿, 다국어, 열람 추적, 멀티 테넌시는 의도적으로 범위 밖(Out of Scope)이며 로드맵에 포함하지 않습니다. 데이터 저장소는 노션이 담당하므로 자체 데이터베이스·인증 서버·ORM 구축 Task는 없습니다. **로그인 기능은 실제 인증이 아닙니다** — 회원가입·비밀번호 검증·세션 서버가 없는 클라이언트 전용 데모이며, 보안이 필요한 어떤 용도로도 사용하지 않습니다.

### 기술 스택 (프로젝트 규약 준수)

- **프레임워크**: Next.js 16.2 (App Router) + React 19 + TypeScript(strict), React Compiler 활성화(수동 메모이제이션 금지)
- **스타일**: Tailwind CSS v4 (CSS-first, `globals.css` 관리) + shadcn/ui(base-nova) + lucide-react + `cn()`
- **데이터 소스**: Notion API(`@notionhq/client`), 서버 컴포넌트에서 직접 페칭
- **검증/타입**: zod v4로 Notion 응답 검증 및 내부 타입 변환
- **PDF**: `@react-pdf/renderer` + Pretendard 서브셋 폰트 임베딩
- **캐싱**: `unstable_cache` + `revalidate: 60`
- **로그인 상태**: 전역 상태 라이브러리 없이 `usehooks-ts`의 `useLocalStorage` 훅으로 `localStorage` 직접 관리 (신규 의존성 없음)
- **폼**: `react-hook-form` + `zodResolver` + zod 스키마 (로그인 폼 포함)
- **컨벤션**: RSC 기본, `'use client'` 최소화, named export(page/layout 제외), 파일명 kebab-case, 컴포넌트명 PascalCase, 탭 들여쓰기, UI 텍스트 한국어

### 현재 코드베이스 상태 (완료됨 — Task 아님)

- 견적서 뷰어 MVP(Task 001~010) 완료: 토큰 기반 웹 뷰, Notion 연동, PDF 다운로드, 60초 캐싱까지 구현 및 검증됨 (상세 이력은 `docs/roadmaps/ROADMAP_v1.md` 참조)
- 전역 레이아웃: `src/app/layout.tsx`(Header/Footer/ThemeProvider 조립), `src/components/layout/header.tsx`(현재 브랜드명 + 테마 토글만 노출, 로그인 상태 UI 없음)
- 테마 인프라: `theme-provider.tsx`, `theme-toggle.tsx` (next-themes)
- shadcn UI: `badge`, `button`, `card`, `dialog`, `dropdown-menu`, `field`, `input`, `label`, `select`, `separator`, `sheet`, `table` 등 로그인 폼 구현에 필요한 컴포넌트 모두 설치되어 있음 — 신규 shadcn 컴포넌트 추가 불필요
- `usehooks-ts` 의존성 이미 설치됨 (`useLocalStorage` 사용 가능)
- **미설치**: 없음 (로그인 기능에 신규 npm 의존성 불필요)

## 개발 단계

**Phase 1~4(Task 001~010)는 견적서 뷰어 MVP로 이미 완료되었습니다.** 상세 구현 이력·변경 사항 요약은 `docs/roadmaps/ROADMAP_v1.md`를 참조하세요. 이 문서는 그 위에 **간이 로그인 기능(Phase 5)**을 추가하는 고도화 로드맵입니다.

> **진행 상황**: Phase 1~4(Task 001~010) ✅ 완료(v1). Task 011(다크 모드·만료 자동 판정), Task 012(인수 조건 점검)는 v1 기준 아직 미착수 — 이번 고도화 범위 밖이며 별도로 이어서 진행 가능. 다음 우선순위는 **Phase 5: Task 013(로그인 상태 관리 및 헤더 연동)**.

### Phase 1~4: 견적서 뷰어 MVP (Task 001~010) ✅

- ✅ **Task 001~010**: 프로젝트 골격, zod 스키마, 더미 UI, Notion 연동, 접근 제어, PDF 한글 폰트 임베딩, PDF 다운로드, 통합 테스트, 60초 캐싱까지 전부 완료. 전체 내역은 `docs/roadmaps/ROADMAP_v1.md` 참조.
- (미착수, 이번 고도화 범위 밖) Task 011: 다크 모드 대응 및 만료 자동 판정
- (미착수, 이번 고도화 범위 밖) Task 012: 인수 조건 전체 점검 및 마감

### Phase 5: 간이 로그인 기능 (신규 고도화)

> 이 Phase는 **인증이 아닌 데모용 UI 상태**를 추가합니다. 서버 검증·세션·비밀번호 해싱이 전혀 없으며, 사용자명/비밀번호를 입력만 하면 그대로 로그인 처리됩니다. 요구사항(참고사항 1·2)에 따라 회원가입 플로우 자체가 존재하지 않습니다.

- **Task 013: 로그인 상태 관리 훅 및 zod 스키마** - 우선순위
  - `src/lib/auth-schema.ts`(신규): `loginSchema`(zod) — 사용자명 1자 이상 필수, 비밀번호 1자 이상 필수(형식·강도 검증 없음, 값 존재만 확인). 내부 타입 `AuthUser`(username만 보관, 비밀번호는 어디에도 저장하지 않음)
  - `src/hooks/use-auth.ts`(신규, `'use client'`): `usehooks-ts`의 `useLocalStorage<AuthUser | null>("auth-user", null)`를 래핑해 `{ user, login(username), logout() }` 반환. `login`은 검증 없이 `{ username }`을 그대로 저장 — 비밀번호는 받되 저장하지 않음(폼 검증 통과 확인 용도로만 사용)
  - localStorage 키: `auth-user` (단일 키, 세션 개념 없음 — 브라우저를 닫아도 유지, 로그아웃 시 키 삭제)
  - SSR 하이드레이션 불일치 방지: `useLocalStorage`는 클라이언트에서만 실제 값을 읽으므로, 헤더의 로그인 상태 UI는 마운트 전 서버 렌더링 시 항상 "로그인 안 됨"으로 렌더링되고 클라이언트에서 즉시 갱신됨(레이아웃 시프트는 감수 — 이 프로젝트 규모에서 skeleton 처리는 과설계)
  - **테스트 체크리스트**: 없음(순수 로직·훅 단위 — 다음 Task에서 실제 UI로 통합 검증)

- **Task 014: 로그인 페이지 구현**
  - `src/app/login/page.tsx`(신규, RSC 골격 + 클라이언트 폼 분리): 사용자명·비밀번호 입력 폼
  - `src/components/auth/login-form.tsx`(신규, `'use client'`): `react-hook-form` + `zodResolver(loginSchema)` + shadcn `Field`/`Input`/`Label`/`Button` 조합. 제출 시 `useAuth().login(username)` 호출 후 홈(`/`)으로 `router.push` 리다이렉트
  - 이미 로그인된 상태로 `/login` 접근 시 홈으로 즉시 리다이렉트(다시 로그인 폼을 보여주지 않음)
  - 에러 메시지: 사용자명 또는 비밀번호 미입력 시에만 zod 필수 검증 메시지 표시(그 외 실패 케이스 없음 — 검증 자체가 없으므로 "로그인 실패"는 발생하지 않음)
  - UI 텍스트 한국어, 폼 레이블·버튼 텍스트는 기존 컴포넌트 톤(간결한 안내문) 준수
  - **테스트 체크리스트**: Playwright MCP — 빈 값 제출 시 유효성 에러 노출, 임의 사용자명·비밀번호 입력 후 제출 시 검증 없이 즉시 로그인 처리, 로그인 후 헤더에 사용자명 반영, 이미 로그인 상태에서 `/login` 접근 시 홈으로 리다이렉트

- **Task 015: 헤더에 로그인 상태 연동 및 로그아웃**
  - `src/components/layout/header.tsx` 수정: `useAuth()`로 로그인 여부 분기
    - 미로그인: 기존 UI(브랜드명 + 테마 토글) + "로그인" 링크(`/login`) 추가
    - 로그인됨: 브랜드명 + 테마 토글 + 사용자명 표시(shadcn `DropdownMenu` 트리거로 "OO님" 노출) + 드롭다운 내 "로그아웃" 액션
  - 로그아웃 클릭 시 `useAuth().logout()` 호출 후 현재 페이지 유지(리다이렉트 불필요 — 견적서 열람은 로그인과 무관하게 항상 공개)
  - 헤더가 `'use client'`로 전환되는 부분은 사용자명 표시 영역만 최소 분리(브랜드 링크·테마 토글은 기존 구조 유지) — 기존 RSC 우선 컨벤션 준수
  - **로그인 상태와 견적서 열람 권한은 완전히 무관함을 명시**: `/quote/[token]` 접근 제어(Task 007)는 이번 Phase로 인해 전혀 변경되지 않음 — 로그인 여부와 무관하게 토큰만으로 열람 가능한 기존 동작 유지
  - **테스트 체크리스트**: Playwright MCP — 미로그인 시 헤더에 "로그인" 링크 노출, 로그인 후 헤더에 사용자명 노출, 새로고침해도 로그인 상태 유지(localStorage 지속성), 로그아웃 후 헤더가 미로그인 상태로 복귀, 로그인 상태가 `/quote/[token]` 열람 가능 여부에 영향 없음을 확인, 다크 모드에서 드롭다운 대비 확인

- **Task 016: Phase 5 통합 검증**
  - Playwright MCP로 로그인→헤더 확인→새로고침 유지 확인→로그아웃 전체 플로우 E2E 검증
  - 엣지 케이스: 사용자명에 특수문자·긴 문자열 입력(XSS 이스케이프는 React 기본 동작으로 충족 확인), 비밀번호 필드가 `type="password"`로 마스킹되는지, localStorage를 개발자 도구로 직접 삭제한 뒤 새로고침 시 자동 로그아웃 처리되는지
  - `npm run lint` / `npm run build` 통과
  - **테스트 체크리스트**: 위 엣지 케이스 전건 + Task 013~015 체크리스트 재확인(회귀 없음 확인)
